Классификатор комментариев: разделение положительных и отрицательных отзывов, авторизация, сохранение запросов и результатов

Цель проекта: приложение, в котором пользователь вводит текст отзыва или комментария и получает результат (положительный или отрицательный), а также видит историю своих запросов после входа в систему. В лабараторной №1 нужно реализовать только интерфейс на демонстрационных данных без настоящего сервера и базы данных.

Реализовано в проекте:
1.	Проект создан на React + TypeScript при помощи сборщика Vite.
2.	В качестве библиотеки UI-компонентов используется Ant Design (antd). Она даёт готовые кнопки, поля ввода, таблицы, уведомления с единым оформлением.
3.	Реализована клиентская маршрутизация (react-router-dom) между четырьмя экранами: «Вход», «Регистрация», «Классификатор» и «История».
4.	На главном экране пользователь вводит текст комментария и получает результат - метку «положительный» или «отрицательный». Сейчас эта классификация выполняется демонстрационной функцией в браузере по ключевым словам, а не настоящей моделью.
5.	Экран «История» показывает заранее подготовленный список запросов и результатов.
6.	Экраны «Вход» и «Регистрация» содержат формы с проверкой заполнения полей, но пока не обращаются к серверу.

Проект использует внешние библиотеки (React, Ant Design, react-router и тд), перечисленные в файле package.json. Сами файлы этих библиотек в архиве не передаются - они скачиваются автоматически командой npm install и складываются в папку node_modules. Чтобы запустить приложение, используется команда npm run dev. После этого показывается адрес, на которомможно просмотреть приложение локально (обычно это http://localhost:5173/)




Лабораторная работа №2
В ходе выполнения второй лабораторной работы был реализован полноценный backend:
1. Настроено подключение к БД: Развернута база данных PostgreSQL, настроено подключение через SQLAlchemy (сессии, движок).
2. Спроектирована модель данных: Созданы две связанные таблицы (users и classification_requests) с каскадным удалением истории.
3. Реализован CRUD: Написаны операции создания, чтения, обновления и удаления для обеих сущностей.
4. Валидация данных: Настроены Pydantic-схемы для проверки входящих данных.
5. Обработка ошибок: Реализованы ответы API с кодами 404 (не найдено) и 400 (некорректные данные/email занят).
6. Бизнес-логика: Добавлен сервис классификации текста и хеширование пароля (SHA-256).

В PostgreSQL созданы две связанные таблицы:
1. users - Пользователи
Поле	              Тип	         Описание
id	                integer	       Первичный ключ
email	            string	       Уникальный, используется для входа
name	            string	       Имя пользователя
hashed_password	    string	       Хеш пароля (SHA-256)
created_at	        datetime	   Дата регистрации (авто)

2. classification_requests - История запросов
Поле	      Тип	           Описание
id	        integer	         Первичный ключ
user_id	    integer	         Внешний ключ на users.id
text	    string	         Исходный текст комментария
label	    string	         Результат: "positive" или "negative"
confidence	float	         Уверенность (0–1)
created_at	datetime	     Дата запроса (авто)

Связь: Один пользователь может иметь много запросов. При удалении пользователя его история удаляется (каскадное удаление).

После запуска сервера интерактивная документация доступна по адресу: http://127.0.0.1:8000/docs

Пользователи (/users)
POST /users/ - Создать пользователя.
GET /users/ - Получить список пользователей.
GET /users/{id} - Получить пользователя по ID.
PATCH /users/{id} - Изменить email и/или имя.
DELETE /users/{id} - Удалить пользователя (вместе с историей).

Запросы на классификацию (/requests)
POST /requests/ - Создать запрос (backend сам вычисляет label/confidence).
GET /requests/ - Список запросов (с фильтрацией ?user_id=).
GET /requests/{id} - Получить один запрос по ID.
PATCH /requests/{id} - Изменить текст (результат пересчитывается).
DELETE /requests/{id} - Удалить запрос.

Коды ошибок: 404 - запись не найдена, 400 - некорректные данные.

entities — сущность «запись истории»: типы, мок-API, контекст и карточка.

shared — переиспользуемые компоненты (PageHeader, SentimentBadge, StateView), утилиты и валидация.


В рамках лабораторной работы №3 реализована интерактивность основных экранов: формы классификации, входа и регистрации, удаление записей из истории с анимацией, кнопки-примеры для быстрого заполнения текста и сброс формы. Для экранов с данными предусмотрены состояния загрузки (Skeleton), ошибки (Result с кнопкой «Повторить») и отсутствия данных (Empty) — как для экрана истории, так и для результата классификации. Добавлена клиентская валидация форм: проверка обязательных полей, корректности email, минимальной длины пароля с обязательным наличием буквы и цифры, совпадения паролей, а также длины и «пустого» текста комментария. Все данные и пропсы компонентов описаны типами TypeScript. Реализованы осмысленные анимации: появление страниц при навигации, карточек истории и результата классификации, плавное удаление записей, а также учтён режим prefers-reduced-motion для пользователей, предпочитающих уменьшенную анимацию. Для проверки динамического поведения до полной интеграции с API используются демонстрационные данные — мок-API истории с режимами ?mock=error и ?mock=empty, позволяющими воспроизвести состояния ошибки и пустой истории.
